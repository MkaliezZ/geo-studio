# GEO Studio 产品需求文档

版本：0.1；日期：2026-10-15；状态：实施基线。产品名暂定 GEO Studio，工程与应用源码采用 MIT。

## 1. 产品目标

为网站运营者、内容团队和小型代理商提供 Windows、macOS、Linux 均可运行的本地 GEO 工作台。完成「采集 → 诊断 → 改写建议 → 人工审核 → 修改后复检 → API 引用监测」闭环。优先组合成熟开源组件，不自己重写浏览器、全站抓取器或模型网关。

技术诊断不需要模型密钥；AI 功能使用用户自己的 API Key。产品不把启发式检查分数称为真实 AI 可见性，不把 API 测量等同于消费端 App，也不承诺某项修改必然增加引用。

## 2. 用户与关键场景

1. 运营者输入网站与页面上限，定位 robots、noindex、正文缺失、canonical、结构化数据等问题，查看原始证据。
2. 内容编辑选择已采集页面或粘贴原文，填写目标问题与改写要求，获得可编辑草稿和逐段差异，保留原文并导出。
3. 品牌负责人配置品牌别名、目标域名、问题集和重复次数，跨已配置模型执行 API 采样，检查品牌提及、真实引用来源及时间趋势。
4. 用户修改网站后重新诊断，以固定规则和 URL 比较新增、已解决、持续存在的问题。

## 3. 平台与交付边界

- Windows x64、macOS x64/arm64、Linux x64：同一 React 界面、Electron 主进程与共享核心。
- 构建矩阵生成 NSIS、DMG/ZIP、AppImage；各系统需分别运行验收，不以 macOS 成功代替 Windows/Linux 实测。
- SiteOne v2.5.1 作为固定版本 CLI，通过子进程和 JSON/文件衔接；下载校验 SHA256，支持用户选择本地组件路径。
- 浏览器渲染按需启用，允许选择已安装 Chromium 路径。缺组件时明确给出可操作状态，不伪造检查结果。
- 不要求最终用户安装 Node、Docker、MySQL。Python robots 辅助程序在发布构建中打包；开发环境可通过 uv 运行。
- 应用关闭时不执行定时任务；重启后至多补一次过期任务，不重复补发所有历史请求。

## 4. 信息架构

左侧导航：网站诊断、AI 改写、引用监测、模型设置。所有功能共享项目选择和本地工作空间。

### 4.1 网站诊断 P0

- 项目：名称、URL、页面上限、是否浏览器渲染；创建、选择、删除项目及其本地记录。
- 采集：同站点页面、HTTP 状态码、最终 URL、Markdown、原始 HTML（在可抓取时）、时间、引擎版本；默认最多 10 页，可设 1–100。
- 任务：待执行、执行中、取消、失败、完成；进度轮询、超时、错误详情；禁止并行运行重复采集。
- 检查：抓取失败与未知状态；robots 按 bot/URL 判定；noindex/nosnippet/X-Robots-Tag；title、description、canonical；JSON-LD 语法与类型；H1、正文、可读取性。
- JS 对照：原始和浏览器 Markdown 差异是观察证据；仅内容短或中文空格少不能推断 JS-only。
- 结果：严重/建议/信息、通过/失败/未知、证据、规则版本、来源和修改建议。没有数据的检查显示 unknown。
- 历史对比：相同项目最新两次完成诊断，按 ruleId+URL 对齐；展示已解决/新增/持续问题及内容变化。
- 导出：JSON 与 Markdown，包含范围、失败页和方法。导出不含 API Key。

### 4.2 AI 改写 P0

- 输入来源：已采集正文或手动粘贴；目标问题、目标读者、语气/约束、提供商选择。
- 真实 API 请求；发送前显示提供商与内容会离开本机的说明。密钥缺失时直接阻止调用。
- 固定约束：不捏造事实、引用、统计、资质和用户案例；无法确认的事实标注需核实；输入是待编辑数据而不是系统指令。
- 原文与草稿并排；逐行差异、草稿编辑、保存版本、导出 Markdown；不自动发布或覆盖站点。
- 保留模型、接口、时间、用量、请求结果；传输失败与空响应不生成成功记录。

### 4.3 引用监测 P0

- 监测配置：品牌、别名、目标域名、每行一个问题、多个提供商、每题重复 1–3 次；一次最多 30 次请求。
- 首批协议：OpenAI Responses（强制 web_search）、Perplexity Agent API（搜索结果映射）、OpenAI-compatible Chat（仅观察回答/链接，不声称联网）。
- 每次采样保存：问题、回答、模型、API endpoint、时间、联网证据、引用（URL/标题/来源类型）、品牌提及、目标域引用、token usage、错误。
- 只有提供商引用字段或搜索结果中被回答明确引用的 URL 进入 citation 指标；回答中自行生成的 Markdown 链接单列，不计真实引用。
- 搜索来源列表与回答引用分开；无联网证据的回答不进入联网引用率分母；失败采样不计为「未引用」。
- 提及率：有效文本采样中包含品牌/别名的比例。英文按边界匹配，中文允许连续匹配。
- 引用率：联网证据成立的有效采样中，引用了目标域名或其子域的比例。没有合格分母时显示「无有效联网样本」。
- 历史批次、按提供商统计、失败次数、引用来源列表与可点击 URL；手动复测和监测配置删除。
- 定时：手动、每小时、每天；仅应用开启时执行。显示下次采样时间、可暂停；重叠任务跳过。

### 4.4 模型与组件设置 P0

- 提供商配置：名称、协议、Base URL、模型/Perplexity preset、API Key；保存、删除、连接测试。
- 支持多个配置并存；OpenAI-compatible 使用用户指定地址；不向配置以外的主机转发密钥，不跟随 API 重定向。
- 连接测试发起一次小请求，结果明确提示可能产生 API 费用。
- Electron safeStorage 加密持久化密钥；无法获得安全存储时只允许会话内使用并明确标注，绝不静默明文落盘。Linux basic_text 后端不视为安全持久化。
- 渲染进程不能读回密钥；日志和导出不含密钥。浏览器开发预览仅会话密钥。
- 组件管理：显示 SiteOne/Python robots/Chromium 状态、版本与路径；按用户操作下载固定且验签摘要匹配的引擎。

## 5. 复用决策

Electron + React/Vite；SiteOne MIT；Cheerio MIT；Turndown MIT；diff BSD；Protego BSD-3-Clause 通过 Python 辅助程序调用。独立 robots 判定覆盖 SiteOne 自带采集策略的局限。保留第三方许可证；完整依赖清单随发行物产生。

## 6. 存储与安全

应用私有数据目录保存项目、诊断、改写和监测记录，schemaVersion=1。写入采用原子替换；本地文件权限尽可能为 0600/目录 0700。密钥独立加密文件，不进入普通状态 JSON。

网站内容按不可信数据处理：仅展示为文本；不在带 Node 权限的窗口执行；IPC 白名单和参数验证；外部 URL 只允许 http(s)。应用只加载打包文件或开发固定源。预览服务仅绑定 loopback 并验证 Origin，不能作为公开服务部署。

## 7. 验收标准

| 编号 | 验收 |
|---|---|
| A1 | 安装后启动统一工作台；Windows、macOS、Linux 分别有构建配置与 CI；未实测平台明确标注 |
| A2 | 无 Key 可运行受控站点诊断，能识别 404、noindex、robots 路径限制与中文正文 |
| A3 | 静态短页不误判 JS 依赖；原始/渲染对照可展示 |
| A4 | 取消任务会终止子进程；异常/超时记录失败，不显示完成 |
| A5 | 修改受控页面后复检能报告问题解决；导出与历史持久化可用 |
| A6 | 提供商可保存/删除/测试，密钥不出现在 state、日志、导出和渲染读取接口 |
| A7 | 改写真实适配层与模拟供应商契约测试通过；没有真实 Key 时标为未完成外部连通性验收 |
| A8 | 引用提取、域名边界、分母、失败、无联网与重复采样有行为测试 |
| A9 | 定时仅应用运行时执行，重启不会重复补发多批任务 |
| A10 | 真实 UI 创建项目→诊断→复检；改写输入/草稿/导出；监测配置/执行/来源；模型表单可操作 |

## 8. 非首版目标与效果边界

不做自动登录采集消费端 AI App、自动改站点/发布、爬虫 IP 伪装、云账户/团队协作、操作系统后台 daemon、生产认证或保证引用增长。可完整使用的首版不要求覆盖所有模型厂商的专有协议。

PRD 范围不因本机平台而收缩。功能已实现、契约测试通过、实际供应商连通、跨系统运行、可签名发布必须分别报告。

## 9. 里程碑

M1：PRD、设计系统、跨平台工程与本地存储。M2：诊断与复检。M3：密钥、改写和引用监测。M4：任务/定时、导出、回归、安装包和平台矩阵。以验收证据更新 IMPLEMENTATION.md，不用界面占位冒充功能完成。
